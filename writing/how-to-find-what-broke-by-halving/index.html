How to find what broke by halving

Something worked last month and doesn't now, and sixteen things changed in between. Checking them one by one can take sixteen tries. Testing the middle and discarding half each time takes four.

  1. 1

    Find one good state and one bad one

    You need a point where it worked and a point where it doesn't. Everything that changed in between is a suspect.

  2. 2

    Test the middle

    Go back to the state halfway between and check it. If it works, the cause is in the second half.

  3. 3

    Throw away the half that's fine

    Each test cuts the suspects in half, whichever way it comes out. Both results are useful.

  4. 4

    Repeat until one is left

    Keep testing the middle of what's left. Sixteen suspects take four tests.

  5. 5

    Count the tests

    Halving grows slowly: a thousand suspects take about ten tests, a million about twenty.

In short

  • It needs a quick, reliable test that says works or doesn't. Build that test first.
  • It works on code history (git bisect), recipe changes, settings, long spreadsheets and wiring.
  • If the problem only shows up sometimes, run each test more than once before you trust it.
