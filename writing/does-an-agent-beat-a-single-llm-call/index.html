Does a four-agent loop beat a single LLM call? I measured it

Multi-agent systems demo well. I wanted to know whether mine actually beats the simple alternative, so I ran both on the same 100 questions, with the same model and the same search index, and compared them question by question.

Short answer: yes, by 12 points, at about 6× the LLM calls. The research agent (a planner, researchers, a critic and a synthesizer) answered 86% of the questions correctly. A single call that retrieves 10 paragraphs and answers got 74%. The paired difference is +12 points, with a 95% confidence interval of +4 to +20.

The setup

  • Questions: 100 from HotpotQA (Yang et al., 2018), a dataset where each answer needs two Wikipedia paragraphs. Half are "bridge" questions (find A, then a fact about A), half compare two things.
  • Retrieval: one BM25 index over the roughly 1,000 paragraphs that come with those questions, including eight look-alike distractors per question. Both systems search the same index.
  • Model: Gemini 3.5 Flash-Lite for both systems and for the grader, on the free tier.
  • Scoring: a pass/fail LLM judge against the gold answer, exact match and F1 on the short answer, and how many of the two needed paragraphs each system retrieved. Every number has a 95% bootstrap interval.

Differences are paired: the same questions for both systems, with 95% bootstrap intervals. Latency isn't compared because both ran under a free-tier rate limit, so most of the measured time was waiting.

Where the gain comes from

The agent won 15 questions, lost 3 and tied 82. In 13 of the 15 wins, the single call had answered that the sources were insufficient. In 11 of them, its one search had found only one of the two paragraphs it needed. The agent's searches found both in 14.

A typical case: "What year did the prison where William Penn wrote No Cross, No Crown stop being used as a prison?" The single call found the Tower of London but no date, and gave up. The agent split it into "Where was Penn imprisoned?" and "When did that prison stop being used as one?", and the second search found the answer: 1952.

The critic earned its place on the hardest questions. It accepted the first round 74 times and asked for a second round 26 times. On those 26 the single call managed 54% and the agent 77%.

Where it loses

  • It over-answers comparisons. Asked whether Pueraria or Pleiospilos is a flowering plant, the single call said Pleiospilos; the agent said both. Longer answers invite claims the sources don't support.
  • Its follow-ups can be vague. The planner writes every sub-question before any search, so the second one can't name what the first one found. In the William Penn case it asked about "this prison" and got lucky because the search matched the word.

Can the grader be trusted?

The same model answered and graded, so a second evaluator, different from the judge, graded 40 randomly chosen answers by hand against the gold answers, without knowing which system wrote them or what the judge said. It agreed with the judge on 39 of 40 (Cohen's κ = 0.92). The one disagreement was the judge being strict: the gold answer was "Plymouth Gin" and the agent said "gin".

What I'd change next

  • Sequential hops: let each sub-question see what earlier ones found.
  • Shorter answers for comparison questions.
  • Routing: run the single call first and the agent only when it gives up. Simulated on these results it would score about 87% at about 2 calls per question. That's a hypothesis for the next run, not a result.

Limits

One hundred questions give intervals of about ±9 points per system, so the overall gain is clear and the comparison-question gain isn't. It's one small model on Wikipedia-style questions with short answers. Everything is reproducible: the code, the question sample, every answer and the second evaluator's grades are in agent-benchmark on GitHub.
