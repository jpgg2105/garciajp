How AI is changing software development

AI isn't replacing developers, but it is changing what the job looks like. This explainer walks through the main ideas from a video on where software development is heading, from handing whole features to agents to keeping those agents safe.

  1. 1

    From autocomplete to whole features

    AI used to suggest the next line, and fixing its output often took longer than writing the code yourself. Now coding agents take a whole feature: they read the codebase, write the code, run the tests and merge the change.

  2. 2

    Write a spec, not a chat

    Different models read the same prompt differently, and arguing with an agent wastes time. A written spec with the goal, the requirements and what counts as done gives the agent something clear to build and check against.

  3. 3

    From implementing to conducting

    For decades the bottleneck was how fast and how well you could write code. Now the valuable part is deciding what to build: setting goals, making architecture decisions that matter a year from now, and splitting work into milestones agents can finish.

  4. 4

    Engineer the context and the loop

    A model only sees what fits in its context window, so you choose what goes in: relevant code, tools, skills and data from MCP servers. Then, instead of prompting back and forth, you design a loop: you set the goal and when it's done, and the agent iterates until it gets there.

  5. 5

    Know how the model runs

    The model's weights sit in GPU memory, and every token of the conversation adds to a KV cache next to them until memory runs out. Models also have no real sense of time: one may estimate weeks for a game it can prototype in minutes.

  6. 6

    Keep agents in a sandbox

    An agent with access to private data, untrusted content and a way to send data out can be tricked by hidden instructions, for example in a pull request. Running it in a disposable sandbox with no secrets inside limits what a hijacked agent can do.

In short

  • Skills, automations and sub-agents extend the same idea: reusable instructions, work triggered by events, and helpers that investigate a problem and report back.
  • The video quotes Andrew Ng's line that AI is the new electricity: like the power grid, it will need engineers who keep it reliable, safe and available.
  • Developers who are strong at architecture and critical thinking gain the most as coding agents improve.
  • The three-part risk in step 6 is what Simon Willison calls the lethal trifecta for AI agents.
  • The memory figures match an 8-billion-parameter model like Llama 3 8B at 16-bit precision. The other examples in the animation are illustrative.
