How I would build it

  • In Node, inside your test first workflow. The reorder math gets unit tests for each edge case before any model is involved.
  • Spike and stockout detection per channel, so one marketplace promo does not inflate the order.
  • The model only writes text from a fixed set of numbers. A validator compares every number in its output with the engine's output.
  • A shadow mode first. Suggestions run quietly next to what buyers actually order, and we compare before anyone sees them.

What I would check first

  • How reorder suggestions work today and how often buyers override them.
  • Whether case packs, minimum orders and supplier calendars are stored per supplier.
  • Which channels cause the most stockouts and which cause the most dead stock.
